# MSS54HP CSL '0401' — クイックステアリングラック装着時の DME 調整

対象: BMW E46 M3、MSS54HP、CSL '0401'。純正ラック → クイックレシオラックへの交換。

---

## 0. 結論 — 触るのは実質 1 箇所

**DME はステアリングの制御器ではない。** 舵角（`LWS_LRW`、CAN 0x1F5 受信）を使う経路は
バイナリ全体で 3 つしかなく、そのうちエンジン挙動に効くのは 1 つだけである。
フライホイールのときのような広い調整範囲は存在しない。

| 順位 | パラメータ定義名 | XDFアドレス | 何が起きるか | 効き |
|---|---|---|---|---|
| 1 | `KL_MD_RES_LRW` | 0x97D8 (master) | x 軸ブレークポイントが新ラックのフルロック角を超え、**トルクリザーブが永久にゼロになる**。連鎖してアイドル制御の点火権限 `MD_LLR_TZ` が永久に閉じる | **要対応** |
| 2 | `KL_FZ_RADIUS_LRW` | 0xB42A (master) | 舵角→旋回半径モデルがラック比ぶんズレ、DME の横 G 推定が過小になる | 二次（オイルレベル補正と SMG のみ） |
| 3 | `K_TEFC_LRW_DELTA` | 0x4010 (slave) | タンク漏れ診断の「走行中」判定が出やすくなる方向 | ほぼ無視可 |

**そして、答えではないもの。** Servotronic（`KL_SERVO_SPORT` / `KL_SERVO_KOMFORT` ほか
計 14 パラメータ）は、ステアリングが重い・軽いの話なので真っ先に手が伸びる場所だが、
**この較正では丸ごと停止している。** `servo_mode_calc` @ `f:master:02d1e4` に逐語で:

```
SERVO_MODE = 0   [if ((SCHALT_S_ST & 0x20) == 0) || (K_SERVO_CTRL == '\0')]
```

`K_SERVO_CTRL`（0xC16E / 0x8C16E）= 0 なので `SERVO_MODE` は恒久的に 0。
Servotronic 系を何を書き換えても操舵力は 1 g も変わらない。

## 1. なぜ効くのか — ラック比とは何を変えるか

クイックラックは、**同じ切れ角に要するハンドル角を 1/k に縮める**（k = 新ラックが
何倍クイックか）。タイヤ側の切れ角・ラック力・ポンプ負荷そのものは変わらない。
変わるのは「ハンドル角」という**入力軸の目盛り**だけである。

DME が舵角を使う経路はすべて「ハンドル角 → 何か」の写像なので、**例外なく k 倍だけ
横方向にズレる**。ゲインの話ではなく軸の話なので、対処も一律「x 軸を k 倍する」で済む。

### 純正ラック比は DME 自身が知っている

`KL_FZ_RADIUS_LRW` は舵角 → 旋回半径の写像である。自転車モデル
`δ = atan(L / R)`（L = E46 ホイールベース 2.731 m）で逆算すると、純正の
ステアリングレシオが直接出てくる:

| ハンドル角 [deg] | 半径 R [m] | 換算 切れ角 [deg] | 含意されるレシオ |
|---|---|---|---|
| 1.006 | 2315.4 | 0.068 | 14.89 : 1 |
| 4.988 | 463.1 | 0.338 | 14.76 : 1 |
| 10.019 | 231.5 | 0.676 | 14.82 : 1 |
| 15.006 | 154.4 | 1.013 | 14.81 : 1 |
| 22.488 | 102.9 | 1.520 | 14.79 : 1 |
| 30.012 | 51.4 | 3.041 | **9.87 : 1** ← 外れ値 |
| 74.987 | 30.8 | 5.067 | 14.80 : 1 |
| 204.094 | 11.2 | 13.704 | 14.89 : 1 |
| 542.763 | 4.0 | 34.323 | 15.81 : 1 |

9 点中 8 点が 14.76–14.89:1 に収まり、フルロックは 542.76° = **3.02 回転
(lock-to-lock)** で E46 M3 の公称値と一致する。この一致は同時に、XDF の
`x*0.04375`（Grad）というスケーリング解釈が正しいことの独立した裏づけでもある
（フライホイール解析ではこの軸デコードを未検証として残していた）。

30.012° の点だけが飛んでいる（他と同じ比なら R ≈ 77 m のはずが 51.4 m）。
純正較正側の入力ミスの可能性が高いが断定はできない。実害は「30° 付近だけ横 G を
過大評価する」ことで、後述のとおり消費先が限られるため実質無害である。

### 交換後の比を出す

**この文書の全係数は k に依存する。まず k を実測すること。** 手順は単純で、
ロック・トゥ・ロックの回転数を数えるだけでよい:

```
k = 新ロック・トゥ・ロック回転数 / 3.02
新フルロック角 [deg] = 543 × k
```

参考値（実測に置き換えること）:

| 新ラック | lock-to-lock | k | 新フルロック角 |
|---|---|---|---|
| 純正 | 3.02 回転 | 1.000 | 543° |
| やや速い | 2.7 回転 | 0.894 | 485° |
| 一般的なクイック | 2.4 回転 | 0.795 | 432° |
| かなり速い | 2.2 回転 | 0.728 | 396° |

## 2. 本命 — `KL_MD_RES_LRW`：舵角がアイドルの点火権限を握っている

これがこの調査で唯一の重要な発見である。**据切り時のパワステ負荷に備えるトルク
リザーブが、そのままアイドル制御の高速アクチュエータの ON/OFF スイッチになっている。**

### 純正資料が設計意図をそのまま書いている

Funktionsrahmen 1.0 p.32「10.2. MOMENTENRESERVE BEI STARKEN LENKEINSCHLÄGEN」の要旨:

> ステアリングが**エンドストップに達すると**パワステポンプが大きなトルクを吸い、
> アイドルでは回転が落ち込み、場合によってはエンストに至る。充填増加による
> アイドル調速器の応答は**吸気の輸送遅れのため遅すぎる**。そこで
> **ハンドル切れ角に応じてあらかじめトルクリザーブを作っておき**、
> アイドル目標回転を下回ったときに**点火進角による高速なトルク増加**を可能にする。

そして算出手順が明記されている:

```
・Betragsbildung des Lenkwinkels          （舵角の絶対値化）
・KL_MD_RES_LRW = f( lrw_abs )            （このカーブを舵角絶対値で引く）
・K_MD_RES_LRW_DELTA で変化率制限         （→ md_res_lrw_roh）
md_res_lrw_st  Bit 0: 作動条件成立
               Bit 1: 介入アクティブ（介入トルクが非ゼロ）
```

**bit0 / bit1 の意味が復元コードと完全に一致している**（`V < K_MD_RES_LRW_V` で bit0、
`MD_RES_LRW_ROH != 0` で bit1）。索引が舵角絶対値であることも明記されている。

つまりこの機能は「**エンドストップでのエンスト防止**」のために存在し、その手段が
「点火の高速権限を開けること」である。クイックラックはエンドストップの角度そのものを
動かすので、**BMW がこの機能で防ごうとした症状が、まさに設計どおり再発する。**

なお p.32 の見出しには「NICHT IN EVT IMPLEMENTIERT!」（EVT では未実装）という注記が
あるが、0401 では `md_res_calc` と `lfr_calc` のゲートが実在するので、この注記は別の
ソフトウェア系列を指している。

復元コードで確定している連鎖（`md_res_calc` @ `f:master:017b9e` → `lfr_calc` @
`f:master:0266b8`）:

```
md_res_calc:
  MD_RES_LRW_ST |= 1                  [if V < K_MD_RES_LRW_V (25 km/h) && (V_ST & 0x40) == 0]
  MD_RES_LRW_ROH = { MD_RES_LRW_ROH + K_MD_RES_LRW_DELTA
                   | MD_RES_LRW_ROH - K_MD_RES_LRW_DELTA }     ← 50 Nm/s でランプ
  MD_RES_LRW_ST |= 2                  [if MD_RES_LRW_ROH != 0]
  MD_RES_LRW_ST &= 0xfd               [if MD_RES_LRW_ROH == 0]
  MD_RES = max(MD_RES_LRW, MD_RES_KATH)

lfr_calc:
  MD_LLR_TZ = 0                       [if (K_LFR_CONTROL & 0x10) == 0 || (MD_RES_LRW_ST & 2) == 0]
  MD_LLR_TZ = (LFR_MD_TZ + 7) >> 3    [otherwise]
```

`MD_LLR_TZ` はアイドル調速器がトルクを**点火で**動かすための項で、空気経路より一桁
速い。それが `MD_RES_LRW_ST` bit1 に、つまり「舵角が `KL_MD_RES_LRW` の非ゼロ域に
入っているか」に懸かっている。

### 現状の数値と、なぜ純正でも渋いのか

`KL_MD_RES_LRW`: x = [520.0, 550.0, 560.0, 580.0]°、y = [0, 5, 10, 15] Nm。

純正のフルロックは 543° なので、**純正時点で 520–543° の 23° 幅しか使えず、
取り出せるリザーブは高々 5 Nm 弱**である。550° 以降の 10 Nm / 15 Nm は
物理的に到達不能な位置に置かれている。

### クイックラックで何が起きるか

新フルロック角が 520° を下回った瞬間、**`KL_MD_RES_LRW` は全域が到達不能になる**。
すると `MD_RES_LRW_ROH` は常に 0、bit1 は永久に立たず、`MD_LLR_TZ` は永久に 0 に
クリップされる。症状は「据切り・車庫入れでアイドルが落ちる／エンストしやすい」で、
しかもアイドル制御は点火という速い手段を失ったまま空気経路の PT1 を待つことになる。

2.4 回転（432°）以下のラックでは確実にこうなる。2.7 回転（485°）でも 520° には
届かない。**純正 3.02 回転より少しでもクイックなら、この経路は死ぬと考えてよい。**

### ラック別・無変更のまま放置した場合のリザーブ量

`KL_MD_RES_LRW` を書き換えずに済むのは純正だけである。

| lock-to-lock | k | 新フルロック角 | 無変更時のフルロックでのリザーブ |
|---|---|---|---|
| 3.02 回転（純正） | 1.0000 | 542.8° | 3.80 Nm |
| 2.90 回転 | 0.9603 | 521.2° | 0.20 Nm |
| 2.80 回転 | 0.9272 | 503.2° | **0（到達不能）** |
| **2.70 回転（Z3 非M）** | **0.8940** | **485.3°** | **0（到達不能）** |
| 2.60 回転 | 0.8609 | 467.3° | 0（到達不能） |
| 2.40 回転 | 0.7947 | 431.3° | 0（到達不能） |

2.8 回転より少しでもクイックなら、この経路は完全に死ぬ。

### 対処 — Z3 非M ラック（2.7 回転）の具体値

`KL_MD_RES_LRW`（XDF 0x97D8 / file 0x897D8, master）の **x 軸のみ**書き換える。
y 軸（0x97E0、[0, 5, 10, 15] Nm）は変更しない。x 軸の量子は 0.04375°/count。

**案 A — 純正挙動の忠実な再現（x 軸を一律 0.894 倍）**

| 点 | 現在 x [deg] | 新 x [deg] | 新 raw | y [Nm] |
|---|---|---|---|---|
| 0 | 520.0125 | 464.9312 | **10627** | 0 |
| 1 | 549.98125 | 491.7062 | **11239** | 5 |
| 2 | 560.0 | 500.6750 | **11444** | 10 |
| 3 | 579.99375 | 518.5250 | **11852** | 15 |

新フルロック 485.3° での取り出し量は **3.80 Nm** となり、純正と完全に一致する
（構成上そうなる）。**まずこれを入れること。** BMW の意図を変えずにラック比だけを
補正する変更なので、リスクが最も小さく、効果の判定も容易である。

**案 B — リザーブを実際に使える位置へ（案 A で不足だった場合）**

純正較正は上 3 点（550/560/580°）がフルロック 542.8° を超えており、**設計上そもそも
5 Nm 弱しか取り出せない**。据切りでの回転落ちが案 A でも残るなら、点をさらに手前へ
寄せて全 15 Nm を使えるようにする。新フルロック角 F = 485.3° に対し
[0.80F, 0.88F, 0.93F, 0.97F]:

| 点 | 新 x [deg] | 新 raw | y [Nm] |
|---|---|---|---|
| 0 | 388.1937 | **8873** | 0 |
| 1 | 427.0000 | **9760** | 5 |
| 2 | 451.2812 | **10315** | 10 |
| 3 | 470.7062 | **10759** | 15 |

フルロック 485.3° は点 3（470.7°）を超えるので、**フルロック保持で 15 Nm まで使える**。
案 A から案 B へは段階的に移ること（一度に入れると、効いたのがラック比補正なのか
リザーブ増量なのか判別できない）。

これはフライホイール文書の推奨 #7（`KL_MD_RES_LRW` ＋ `KL_LFR_TZ_NEG` のペア編集）と
同じカーブへの変更である。**両方を予定しているなら 1 回で済ませること。**

## 3. 二次 — `KL_FZ_RADIUS_LRW`：横 G 推定

`a_quer_calc` @ `f:master:0210c4`（復元済み）:

```
DAT_00ffdabe = PT1_Filter_US( (-LWS_LRW) - K_A_QUER_LRW_OFFSET, DAT_00ffdabe, 0x20 )
FZG_R        = KL_FZ_RADIUS_LRW( ... )                      ← lookup 文は未復元（xref-only）
A_QUER_BER   = ±( ((V_ASC × V_ASC) / FZG_R) + 0x1f ) >> 5
A_QUER_BER   = 0        [if 2 < LWS_STAT]                   ← 舵角センサ異常時は無効
A_QUER_BER   は ±0x7f でクランプ
```

つまり DME は横 G を**測っていない。舵角と車速から推定している。** クイックラックでは
同じ舵角に対する実半径が小さいので、`KL_FZ_RADIUS_LRW` は R を過大評価し、
**横 G は k 倍だけ過小に出る**（k=0.795 なら実際の 79.5% しか見ない）。

### ただし消費先が限られる

`A_QUER_BER` → `asc_a_calc` @ `f:master:013326` → `ASC_AY`（`K_ASC_A_TAU` で PT1）。
`ASC_AY` の読み手を実測で列挙すると:

- `tog_corrections_update` @ `f:master:02e80c` — オイルレベル補正（`TOG_ASCAY_SUM += ASC_AY`）
- `smg_state_supervisor` / `smg_ki_shift_icon_level` — SMG のシフト判断（SMG 車のみ）
- `fsp_build_timer_snapshot_lut` — 故障時のフリーズフレーム環境データ
- `ds2_handler` — DS2 の `asc_ay` チャンネル

**燃調・点火・トルク制御は一切これを読んでいない。** したがって走りには効かない。
直す価値があるのは「オイルレベル表示の精度」と「SMG 車のシフト判断」だけである。
とはいえ対処は x 軸を k 倍するだけなので、`KL_MD_RES_LRW` を触るついでにやればよい。

なお DSC 由来の横 G は `ASC_AY_DPR`（`can_rx_1f3`）として別に存在し、こちらは
ラック比の影響を受けない。

## 5. 作業手順

1. **k を実測する（2 分で終わる、そして全数値がこれで決まる）。**
   ハンドルを片側フルロックから反対側フルロックまで回して回転数を数え、
   `k = 回転数 / 3.02` を出す。Z3 非M の一般的な公称値は 2.7 回転（k = 0.894）だが、
   **年式・仕様で異なる可能性があるので実測値を優先すること。** 2.7 でなければ
   §2 の表の該当行、または `新 raw = round(現在 deg × k / 0.04375)` で引き直す。
2. **`KL_MD_RES_LRW`（0x97D8）の x 軸を案 A の値で書き換える。**
   2.7 回転なら raw = [10627, 11239, 11444, 11852]。y（0x97E0）は不変。
3. **検証。** エンジン暖機後、ニュートラル・アイドルで据切りをフルロックまで行い、
   DS2 ブロック 0x03（`n`, `llr_n_soll`）＋ 0x13（`md_llri`, `lls_tv`, `tz1..tz6`）を
   ログする。
   - 合格: フルロック保持中に `n` の落ち込みが 50 rpm 以内に収まり、`tz1..tz6` が
     動いている（＝点火経路が仕事をしている）
   - 不合格: `tz1..tz6` が動かない → bit1 がまだ立っていない。x 軸をさらに手前へ
4. **`KL_FZ_RADIUS_LRW` の x 軸を k 倍する**（任意）。検証は一定舵角・一定速の定常円で
   DS2 `asc_ay`（ブロック 0x13 offset 60、0.1 m/s²）を読み、`v²/R` の手計算と突き合わせる。

**注意:** 手順 2 はフライホイール文書の推奨 #7 と同じカーブを触る。両方を予定して
いるなら、`KL_LFR_TZ_NEG`（0x9CE6）の充填と一緒に 1 回で入れること。別々にやると
どちらが効いたか判別できない。

## 6. データログ

新規に必要なチャンネルは無い。既存のもので足りる。

| 信号 | ブロック | offset | 用途 |
|---|---|---|---|
| `n` | 0x03 | 0 | 据切り時の回転落ち |
| `llr_n_soll` | 0x03 | 2 | 目標との偏差 |
| `md_llri` | 0x13 | 77 | アイドル積分器（空気経路がどれだけ働いているか） |
| `lls_tv` | 0x13 | 75 | アイドルアクチュエータ duty |
| `tz1..tz6` | 0x13 | 22–32 | **点火経路が動いたかの唯一の判定材料** |
| `asc_ay` | 0x13 | 60 | 横 G 推定（`KL_FZ_RADIUS_LRW` の検証用） |
| `v` | 0x13 | 0 | 25 km/h ゲートの確認 |

`MD_RES_LRW_ST` にも `MD_LLR_TZ` にもライブチャネルは存在しない。**リザーブが
立ったかどうかは直接見られず、`tz1..tz6` が動いたかという間接証拠でしか判定できない。**
ブロック 0x03 と 0x13 の 2 つで足りるので、サンプルレートの分割は最小で済む。

## 7. 未確認事項

1. **Z3 非M ラックの lock-to-lock を実測していない。** 本文書は一般に流布している
   2.7 回転（k = 0.894）を採用しているが、これは公称値であって当該個体の実測ではない。
   Z3 は 1.9 / 2.3 / 2.8 などで仕様差がありうる。**k がこの文書のすべての数値を決める**
   ので、手順 1 で必ず数えること。純正側の 3.02 回転は `KL_FZ_RADIUS_LRW` から
   逆算した値なので、こちらは確度が高い。
2. **`KL_MD_RES_LRW` の lookup 文が未復元。** `md_res_calc`（466 バイト、復元 17 文）の
   **復元された範囲には舵角信号が 1 つも現れない** — `LWS_LRW` を読む関数は
   `a_quer_calc` / `can_rx_1f5` / `tefc` の 3 つだけで、`md_res_calc` は含まれない。
   索引は未復元部分か callee にある。
   したがって次のように切り分けること:
   - **code-confirmed**: `MD_RES_LRW_ROH != 0` → `MD_RES_LRW_ST` bit1 → `MD_LLR_TZ` が
     開く、という連鎖。`K_LFR_CONTROL` = 31 なので bit4 側は常に開いており、
     **この bit1 だけが唯一の閉塞要因**である。
   - **funktionsrahmen-confirmed**: `KL_MD_RES_LRW = f(lrw_abs)` という索引と、
     bit0/bit1 の意味（FR 1.0 p.32 が明記、かつ bit の意味は復元コードと一致）。
   - 単位 `Grad` と `x*0.04375` スケーリングが `K_A_QUER_LRW_OFFSET` /
     `KL_FZ_RADIUS_LRW` と共通であることも傍証になる。

   総合すると索引が舵角であることはほぼ確実だが、**バイナリ上で直接確認したわけではない。**
   実車で確かめる方法は手順 3 のとおり（フルロック保持で `tz1..tz6` が動くか）。

7. **FR とコードで `md_res_lrw` の合成方法が違う。** FR 1.0 p.32 は触媒暖機による
   既存リタード分を**引き算**すると書く
   （`md_res_lrw = md_res_lrw_roh - md_ind_wunsch_begr × md_eta_kath_offset`）が、
   復元コードは `MD_RES = max(MD_RES_LRW, MD_RES_KATH)` という**最大値選択**である。
   0401 はコード側が正。触媒暖機中は挙動が本文書の想定と異なりうるので、
   検証は暖機完了後（`KATH_ST` が落ちてから）に行うこと。
3. **`KL_FZ_RADIUS_LRW` の 30.012 deg 点が外れ値**（他が ~14.8:1 のところ 9.87:1）。
   純正較正のミスか意図的かは不明。
4. **SMG か MT か。** SMG なら `KL_FZ_RADIUS_LRW` の修正はシフト判断に効くので優先度が
   上がる。MT なら実質オイルレベル表示のためだけの変更になる。
5. **ラック交換でパワステポンプの実負荷がどう変わるかは測っていない。** リザーブ量
   （y 軸 = 最大 15 Nm）が新ラックで足りるかは、手順 3 のログで回転落ちを見て判断する
   しかない。足りなければ y も上げる必要があるが、その根拠は本文書には無い。
6. **値の出自。** 本文書の現在値はリポジトリの参照イメージ
   `Full 211323000401PD31_TERRA.bin` をデコードしたもので、対象車両の BIN
   （Community Patch v1 ベース）とは別物である。編集前に自車の BIN で読み直すこと。
