# MSS54HP CSL '0401' — 微開（足を乗せただけ）の「ぐわんぐわん」

対象症状：**アクセルペダルに足を乗せる程度の微開**で、ギアが繋がったまま低速で転がしているとき、
車体が大きく・ゆっくり前後に揺すられる。舵を切るとこれが強まり、デフを引きずるように感じる。

これは [`low_rpm_steering_judder.md`](low_rpm_steering_judder.md) で解決した速くて細かい「ガクガク」
（`kf_rf_soll_tau_up` で消えた）とは**別の現象**である。

> **本稿 v3。**
> v1 は「アイドルバルブは開ループだから犯人ではない」と書いた。誤り。`cfg_m_egas` の分岐を
> 読み違え、この BIN で走っていない側を読んでいた。v2 で訂正済み。
> v3 では **§0 から「これが機構だ」という断定を外した。** 確定した構造と、まだ仮説の因果を
> 分けて書く。v2 の §0 は §1/§2 の構造を「＝ぐわんぐわんの機構」と読ませる書き方だったが、
> **それは検証していない。**

### VE を動かしても治らない理由（**§9.8 で言い直した**）

> **初稿の「両辺が一緒に動く」は誤り。** `MD_RF_ROH` は `KF_MD_MAX_MD_IND_OPT` 由来で
> `kf_rf_soll` とは無関係であり、動かない。

正しくは — **`kf_rf_soll` は一巡ゲインに「傾き」として入る。**
`FR_REGLER` は `RF`（= `kf_rf_soll` の出力）と `MD_RF_ROH` の差を積分するので、
`kf_rf_soll` の**値**を動かせば積分器の落ち着き先が変わるだけ。
一巡ゲインを動かすのは**傾き**であり、0645 と 0744 の差分 12 セルはすべて値の変更である。（§9.8）

## 1. 微開ではスロットルは閉じたままである

`egas_compute_throttle_target` @ `f:master:0270b0`（code-confirmed）：

```c
MD_RF_KORR  = (FR_REGLER * MD_RF_SOLL) >> 15;
ML_SOLL     = (ml_mot * N >> 10) * MD_RF_KORR / 1000 + FRA_ML_ADAPTION;

if (ML_SOLL < ML_SOLL_MAX_LLS) { ML_SOLL_LLS = ML_SOLL;         ML_SOLL_WDK = 0; }
else                           { ML_SOLL_LLS = ML_SOLL_MAX_LLS; ML_SOLL_WDK = ML_SOLL - ML_SOLL_MAX_LLS; }

RF_SOLL_WDK = ML_SOLL_WDK * 1000 / (ml_mot * N >> 10);
WDK_SOLL    = KF_EGAS_WDK(N, RF_SOLL_WDK);
if (cfg_m_egas == 0) { lls_tv_calc(ML_SOLL_LLS); }      // ← この BIN はこちら
```

**優先順位付きの分配である。アイドルバルブが先に取り、余った分だけスロットルが開く。**

- `ML_SOLL_MAX_LLS` ← `KL_LFR_SOLL_MAX_LLS(N)` @ 0x9A32 / 0x9A3E（data-confirmed）：

  | rpm | 600 | 900 | 1500 | 2500 | 3700 | 7000 |
  |---|---:|---:|---:|---:|---:|---:|
  | kg/h | 34.0 | **46.0** | **60.0** | 72.0 | 78.0 | 84.0 |

- 暖機後アイドルの空気要求は 14 kg/h 前後。微開・1300〜1600 rpm でも 20〜35 kg/h 程度。
  **どちらも上限を大きく下回る。**
- `KF_EGAS_WDK` @ 0x83E8 の **`RF_SOLL_WDK` = 0 の行は全回転数で 0.0 %**（data-confirmed）。

→ **`WDK_SOLL` = 0.0 %。スロットル板は制御ループの外にいる。**

> **`cfg_m.egas` @ 0x8012 = 0**（data-confirmed）。この 1 バイトが分岐を決めている。
> `cfg_m_egas != 0` なら `llr_qsoll_calc` が `KF_LLR_QVS_GRUND`（暖機後 14.0 kg/h 一定）で
> バルブを開ループ駆動する。**この BIN はそちらではない。**
> 傍証：`KF_LLS_TV` の y 軸が 11〜85 kg/h で、`KL_LFR_SOLL_MAX_LLS` の 34〜84 kg/h と重なる。
> 実測で潰すなら §5。

## 2. デューティを動かしているのは純積分器

`fr_calc` @ `f:master:0253de`（code-confirmed、逐語）：

```c
FR_RF_DELTA = RF * 10 - MD_RF_ROH;                    // 充填率の実値 − 要求値
FR_ANT_I    = (FR_RF_DELTA < 0) ? KL_FR_INEG(|d|) : KL_FR_IPOS(|d|);
if (|WDK_SOLL - WDK_WORD| <= K_FR_EDK_DIFF)           // 3.0 %
    FR_REG_I = FR_REG_I + (FR_ANT_I >> 4);            // ← 積分のみ。P 項は無い
FR_REG_I  = clamp(FR_REG_I, K_FR_IMIN, K_FR_IMAX);    // 0.800 … 1.200
FR_REGLER = FR_REG_I - 0x8000;
```

**比例項が一行も無い。** 出力 `FR_REGLER` は `MD_RF_SOLL` に乗算され、`ML_SOLL` → `KF_LLS_TV` →
バルブデューティになる。

積分ゲイン `KL_FR_IPOS` / `KL_FR_INEG` @ 0xDFB8・0xDFDA（data-confirmed、XDF 表示）：

| RF 偏差 | 0 | 0.005 | 0.015 | 0.03 | **0.05** | 0.075 | 0.1 | 0.13 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| ゲイン/ステップ | 0 | 0 | 0.0008 | 0.0015 | **0.0020** | 0.0015 | 0.0008 | 0 |

- 不感帯 ±0.005 RF。微開の RF は 0.09〜0.18 なので、**相対で ±3〜5 % の不感帯**（全負荷なら ±0.5 %）。
- ピークは偏差 0.05、10 ms タスクなら **1 秒あたり 20 % of unity**。
  権限が ±20 % なので、**ピークゲインでは約 1 秒で端から端まで振り切る。**
- **ベル形＝偏差が大きいほどゲインが落ちる。** 振れが大きくなるほど戻す力が弱まるので、
  大振幅のサイクルほど維持されやすい。

そして**比例項の代わりになるものが、走行中は何も無い**：

| 経路 | 微開・走行中（V > 2 km/h、クラッチ締結）の状態 | 根拠 |
|---|---|---|
| `LFR_MDP`（アイドル P 項） | `S_KRAFTSCHLUSS && V > K_LFR_V_MAX`(2 km/h) で **強制 0** | `lfr_calc` L93–97 |
| `LFR_MD_TZ`（点火による即応） | 同上で **強制 0**。`KL_LFR_TZ_NEG` も全点 0 | 同上 / 0x9D06 |
| `LFR_MDI`（アイドル I 項） | 970 rpm 超で状態 0x10 → `K_LFR_UEW_MAX` = **5.0 Nm** 上限で減衰 | `lfr_calc` L216–225 |
| `FRA_ML_ADAPTION`（長期学習） | `LFR_ZUSTAND & 2` でしか更新されない → **凍結**（±3.0 kg/h） | `fra_adapt` @ `f:master:0256c6` |
| **`FR_REG_I`** | **生きている唯一の制御器。純積分。** | `fr_calc` |

**遅い積分器がひとつ、遅い電磁弁をひとつ、比例項ゼロで回している。** これがぐわんぐわんである。

## 3. なぜ VE を動かしても変わらないのか

`FR_RF_DELTA = RF × 10 − MD_RF_ROH` で、

- `RF` は `kf_rf_soll(N, aq_rel_rf)` の出力
- `MD_RF_ROH` はトルク構造が要求する充填率

`kf_rf_soll` を書き換えると **両辺が同じ向きに動く**。積分器は新しい釣り合い点まで巻き直すだけで、
**ループゲイン（`KL_FR_I*`）も、遅れ（バルブ＋吸気＋燃焼＋駆動系）も、位相余裕も一切変わらない。**

**リミットサイクルは釣り合い点ではなく位相余裕で決まる。** だから VE をどう動かしても振動は残る。
実車での観察と構造が一致している。

## 4. もう一本の VE 非依存経路 — 点火マップのハード切替

`tz_calc` @ `f:master:02abde`（code-confirmed、逐語）：

```c
if ((ZUSTAND_MOTOR & LL) == 0) { table = &KF_TZ_GRUND; }
else                           { table = &KF_TZ_LL;    }
TZ_GRUND = kfs_wint(&table->sizeX, N, RF);
```

**ブレンドもランプも無い。ビットが変わった瞬間にマップが入れ替わる。**

`cfg_m_egas == 0` なので、LL/TL の判定は**スロットル開度ではなく運転者要求トルク `MD_FW`**
（`zustand_motor_calc` @ `f:master:02c1e2` L48–49・L63–66、code-confirmed）：

| 定数 | アドレス | 値 |
|---|---|---|
| `K_BZ_MD_LL`（LL → TL） | 0xAC08 | **1.0 Nm** |
| `K_BZ_MD_LL_HYST`（TL → LL） | 0xAC0A | **0.5 Nm** |

**帯は `MD_FW` = 0.5 〜 1.0 Nm。** 最大 343 Nm のエンジンで 0.3 % 幅である。
「足を乗せる程度」はまさにこの帯で、**人間の足でここを外して保つことはできない。**
しかも `MD_FW` は `KF_MD_FAHRER(ペダル, N)` なので**回転数でも動く** — 揺れ自体が境界を跨がせる。

切替の代償（両マップを実値で補間、computed）：

| rpm | RF 0.10 | RF 0.14 | RF 0.18 |
|---:|---:|---:|---:|
| 900 | +4.5° | +1.3° | +0.2° |
| 1100 | **+12.0°** | **+8.0°** | +2.5° |
| 1300 | +6.7° | +1.9° | +0.1° |
| 1500 | +7.7° | +3.4° | −0.6° |
| 1700 | +7.4° | +3.4° | −1.4° |

（正 = TL 側が進角。`KF_TZ_LL` は 2×6 で y 軸が RF 0.4／0.6 しかなく、
微開の RF 0.1〜0.18 では **0.4 の行にクランプされる**。data-confirmed）

**点火進角の段差は吸気の遅れを経由しない。ビットが変わったその燃焼から効く。**
駆動系のバックラッシュが開いている微開で、これが繰り返し叩かれる。

## 6. 試す候補（この順で、1 つずつ）

> **これらは「確定した原因への対策」ではなく、§0 の仮説それぞれに対応する試行である。**

### 1. 点火マップの往復を止める — `K_BZ_MD_LL` / `K_BZ_MD_LL_HYST`

**`MD_FW` の実測値を見てから、余裕のある側へ境界を逃がす。**

- 微開の `MD_FW` が **1.0 Nm より上**に乗っているなら → 境界を**下げて** TL に固定する
  `K_BZ_MD_LL` 1.0 → **0.3 Nm**（raw 10 → 3）、`K_BZ_MD_LL_HYST` 0.5 → **0.2 Nm**（raw 5 → 2）
- 微開の `MD_FW` が **0.5 Nm より下**に乗っているなら → 境界を**上げて** LL に固定する
  `K_BZ_MD_LL` 1.0 → **6.0 Nm**（raw 60）、`K_BZ_MD_LL_HYST` 0.5 → **4.0 Nm**（raw 40）

> **制約：`K_BZ_MD_LL_HYST` は `K_BZ_MD_LL` より必ず小さくすること。**
> コードは `(int)((uint)K_BZ_MD_LL - (uint)K_BZ_MD_LL_HYST)` を符号なしで引いてから int に入れる。
> 逆転させると 16 bit で回り込み、比較が常に偽になって TL に入れなくなる（code-confirmed）。

境界を上げる側の副作用：微開まで `KF_TZ_LL`（遅角側）が使われるので、踏み始めが鈍くなる。
境界を下げる側の副作用：アクセルオフの惰行でも TL に残りやすくなり、エンジンブレーキが僅かに弱まる。

### 3. スロットル板をループに戻す — `KL_LFR_SOLL_MAX_LLS`

構造的な対策。上限を下げると微開でも `ML_SOLL_WDK` > 0 になり、**スロットル板が空気の一部を運ぶ。**
スロットルは自前の位置サーボを持つ速い線形アクチュエータなので、PWM 電磁弁より桁違いに素直である。

| rpm | 600 | 900 | 1500 | 2500 | 3700 | 7000 |
|---|---:|---:|---:|---:|---:|---:|
| 現在 (kg/h) | 34.0 | 46.0 | 60.0 | 72.0 | 78.0 | 84.0 |
| **案** | **34.0（据置）** | **30.0** | **30.0** | 72.0（据置） | 78.0 | 84.0 |

**600 rpm の点は動かさないこと。** ここを下げるとアイドルでスロットルが開き始め、アイドル安定性に直接効く。
900 rpm は暖機後のアイドル目標 870 rpm のすぐ上なので、**この変更は必ずアイドルの確認とセットで行う。**

### 触らないこと

## 7. ドライバビリティ・フィルタ — ユーザー実験で効いた 4 つ

実車で `KF_LLS_TV` / `KF_EGAS_WDK` / `KL_MD_DASHPOT_DMD` / `KL_MD_LS_DMD` を戻したところ、
ぐわんぐわんが**明確に悪化**した。以下、確定した構造と、まだ仮説のままの因果を分けて書く。

### 7.1 確定 — 微開では 2D マップが軸の外にいる（data-confirmed）

トルク要求のスルーレート・リミッタ（`FUN_00017052`、`45-drivability-filters.md` 参照）は
`V > K_MD_DF_VMIN`(3 km/h) かつ `N > K_MD_DF_NMIN`(500 rpm) かつ駆動締結で**作動している**。
だが微開（要求トルク 5 Nm 前後、900〜1500 rpm）では：

| パラメータ | 軸の下限 | 微開での挙動 |
|---|---|---|
| `KF_MD_LS_KOMF` | x ≥ 20.0 Nm、y ≥ 1500 rpm | **隅の 1 セル（3.2）に固定**。900〜1500 rpm × 0〜20 Nm が全部これ |
| `KF_MD_DASHPOT` | x ≥ 10.0 Nm | 10 Nm 列に固定（900/1200 rpm = 1.0、1700 rpm = 4.0） |
| `KF_MD_DASHPOT_FAKTOR` | y ≥ 25.0 Nm | 25 Nm 行に固定（1000 rpm = **0.20**）。しかも**イベント中ラッチ** |
| `KL_MD_LS_DMD` | 軸は `D_MD_REL` のみ | 回転数・負荷軸を持たないので**微開にも届く** |
| `KL_MD_DASHPOT_DMD` | 同上 | 同上 |

**→ 微開で分解能を持つスルーレート系パラメータは、軸を持たない 2 本だけである。**
ユーザーが見つけた 2 本がまさにそれであることは、偶然ではなく構造の帰結。
残り 2 本（`KF_LLS_TV` / `KF_EGAS_WDK`）は §1 のとおりアクチュエータ側のゲインそのもの。

### 7.2 確定 — サージ中はレート軸が踏まれない（computed）

`D_MD_REL = MD_WUNSCH_REL − 前回値`（`f:master:0166f6` L45、code-confirmed）。
`MD_WUNSCH_REL` は **%**（`KF_MD_FAHRER` の z が %）。軸換算 `x*5` から **raw 1 = 5 %/s**。

`KF_MD_FAHRER` の微開行（ペダル 4.5 %）は 1100/1400/1500 rpm で 5.5 %、1700 rpm で 4.5 %
→ 回転数感度 **0.005 %/rpm**（1500–1700 帯、それ以外はフラット）。

| サージの想定 | `D_MD_REL` | `KL_MD_LS_DMD` | `KL_MD_DASHPOT_DMD` |
|---|---:|---:|---:|
| ±100 rpm / 1 Hz | 3.1 %/s | 0.997 | **1.000** |
| ±200 rpm / 2 Hz | 12.6 %/s | 0.988 | **1.000** |
| ±300 rpm / 3 Hz | 28.3 %/s | 0.974 | **1.000** |
| ペダルが ±5 % 振れる | 76.8 %/s | 0.930 | 1.000 |

最初のブレークポイント 300 %/s に届くには **2 Hz でペダル振幅 ±19.5 %** が必要。

**→ 0.725→3.0 のランプはサージ中に踏まれていない。**
`KL_MD_DASHPOT_DMD` は最初の 3 点が全て 1.0 なので、50 %/s 以下では**カーブ全体が無効**。

**∴ この 2 本は微開では「レート依存の可変ゲイン」ではなく、ほぼ定数倍として働いている。**
ユーザーの revert で変わったのは **x=0 付近の値＝ループゲインの水準**であって、
レート依存の何かではない。

### 7.3 測定済みだが因果は未確定 — 上げ／下げの非対称

微開・1000 rpm・1 速、レート ≈ 0（§7.2 より）での許可量（Nm/10ms、段別係数込み）：

| 向き | 内訳 | 値 |
|---|---|---|
| 上げ | 3.2 × 0.75(1速) × 1.00(`LS_DMD`) × 0.158(`DELTA_VER` 10 Nm 列) | **0.379** |
| 下げ | 1.0 × 0.60(1速) × 0.20(`DASHPOT_FAKTOR` ラッチ) × 1.00(`DP_DMD`) | **0.120** |
| | **比** | **3.2 : 1** |

回転数を振ると比は 1000 rpm で 3.2、1700 rpm で 0.44（**逆転**）、2000 rpm で 約 1.5。
また `KF_MD_DASHPOT` の 10 Nm 列は 1200→1700 rpm で **1.0 → 4.0（4 倍）**。

> **ここから先は仮説である。**
> 「レートリミッタの上下非対称が整流器として働き、1〜2 Hz のリミットサイクルを維持している」

> 注いでいるかは計算していないし、`MD_DYN_ST` の bit6/bit4 が実車のサージ中に実際に立っているか
> （＝リミッタが本当にクリップしているか）も未測定である。
> **リミッタがそもそもクリップしていなければ、上の比は一度も適用されない。**

#### 決定的な一文

`rf_calc`（逐語）：


`k_rf_cfg` = **0x12**（bit0=0, bit2=0, bit4=1）、`k_rf_hfm_cfg` = **0**。

> `FR_RF_DELTA = RF - MD_RF_ROH` は「実際の充填 − 要求」ではなく
> **「DME 自身の前向きモデルの出力 − トルク構造の逆モデルの要求」。**
> FR ループは空気の実測を一切含まず、**モデルの中だけで閉じている。**

ループ内に異なる周期があり、それ自体が位相遅れになる。

    MD_RF_ROH ──(−)→ FR_REG_I 積分 → FR_REGLER → ML_SOLL

### 9.9 計算式 — `KF_LLS_TV` を `kf_rf_soll` から導く

§9.8 の表をどう出したか。**この節だけで再現できるように書く。**

#### 記号

| 記号 | 意味 | 出どころ |
|---|---|---|
| `ML` | `ML_SOLL_LLS`、アイドルバルブに割り当てられた要求空気量 [kg/h] | `egas_compute_throttle_target` |
| `D` | `LLS_TV_AQ`、バルブのデューティ [%] | `KF_LLS_TV(N, ML)` |
| `A` | `AQ_ABS_LLS`、バルブの開口面積 [mm²] | `KL_AQ_ABS_LLS(D)` |
| `q` | `AQ_REL` [%] | `A / K_AQ_ABS_MAX × 100` |
| `y` | `aq_rel_rf` [%] | `q / kl_aq_rel_rf_fakt(N)` |
| `RF` | 充填率 [0–1] | `kf_rf_soll(N, y)` |
| `FR` | `FR_REGLER`、積分器の出力 [1.0 が中立] | `fr_calc` |

微開ではスロットルの寄与が 0（実測 WDK ≤ 0.1 % → 最大 0.82 mm²）なので `AQ_ABS ≈ A`。

#### 1. 一巡の合成関数

    RF = kf_rf_soll( N,  KL_AQ_ABS_LLS( KF_LLS_TV(N, ML) ) / K_AQ_ABS_MAX × 100 / kl_aq_rel_rf_fakt(N) )

これを `RF = G(ML)` と書く。**4 枚のマップの合成。**

`FR` は `MD_RF_SOLL` に乗算されて `ML` になるので、`FR = 1` 近傍で

    dML/dFR = ML

#### 2. 弾性と開ループゲイン

弾性（無次元）：

    e(ML) = d ln RF / d ln ML = (ML / RF) · dG/dML

数値計算では中心差分（`h = 0.01·ML`）：

    e = [ ln G(ML+h) − ln G(ML−h) ] / [ ln(ML+h) − ln(ML−h) ]

前向きゲイン（`FR` から `RF` へ）：

    dRF/dFR = (dRF/dML)·(dML/dFR) = (e·RF/ML)·ML = **e · RF**

#### 3. 積分ゲイン `Ki`

`fr_calc`（`task_10ms`、code-confirmed）：

    FR_REG_I += KL_FR_INEG(|FR_RF_DELTA|) >> 4        （誤差が負のとき。正なら IPOS）

XDF の換算 `x/(32768·16)` は `>>4` と `32768 = 1.0` を含むので、表示値がそのまま
**1 ステップあたりの `FR` の変化（unity 比）**。タスクは 10 ms なので毎秒 100 ステップ。

    Ki = (1 ステップの表示値) × 100 / (その点の RF 誤差)      [1/s per unit RF error]

`KL_FR_INEG` @ 0xDFEA の各点：

| RF 誤差 | 0.005 | 0.015 | 0.03 | 0.05 | 0.075 | 0.1 | 0.13 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 表示値 /step | 0 | 0.0008 | 0.0015 | 0.0020 | 0.0015 | 0.0008 | 0 |
| **Ki [1/s]** | — | **5.33** | 5.00 | 4.00 | 2.00 | 0.80 | — |

**小誤差側の `Ki` = 5.33 /s を採用**（サージは小振幅から育つため）。

#### 4. 開ループと位相余裕

積分器＋一巡遅れ `Td` なので

    L(s) = (Ki · e · RF / s) · e^(−s·Td)

交差周波数（|L| = 1）：

    ωc = Ki · e · RF          [rad/s]

位相は積分器の −90° と遅れの −ωc·Td なので

    位相余裕 PM = 90° − ωc · Td · (180/π)
    減衰比     ζ ≈ PM / 100        （経験則）
    共振増幅   Q  = 1 / (2ζ)

`Td` = **0.58 s**（Session 954 の `duty` × `rpm` 相互相関の第一ピーク、§9.4 — 実測）。

> **`ωc` は `RF` にも比例する。** 弾性を一律にしても高 RF 側で余裕が落ちる。
> これが §9.8 初稿の「弾性 > 1 = 行き過ぎ」が誤りだった理由（1 ステップゲインは
> `Ki·T·e·RF` ≈ 0.019 で離散不安定の閾値に遠く及ばない。効いているのは位相余裕）。

#### 5. 逆引きの手順（表の作り方）

`RF ∝ ML` を課す（弾性 = 1）。列（回転数 `N`）ごとに：

**(a) アンカー**  現行の `ML = 30` 行のデューティ `D₃₀` を据え置き、そこから比例定数を得る：

    A₃₀ = KL_AQ_ABS_LLS(D₃₀)
    y₃₀ = A₃₀ / K_AQ_ABS_MAX × 100 / kl_aq_rel_rf_fakt(N)
    RF₃₀ = kf_rf_soll(N, y₃₀)
    k = RF₃₀ / 30                                    [RF per kg/h]

**(b) 各行 `ML`**（実測帯にかかる行のみ）：

    RF_target = k · ML
    y  = kf_rf_soll(N, ·)⁻¹ (RF_target)               ← 二分法
    q  = y · kl_aq_rel_rf_fakt(N)
    A  = q / 100 · K_AQ_ABS_MAX
    D_new = KL_AQ_ABS_LLS⁻¹(A)                        ← 線形逆補間
    D_new = clamp(D_new, K_LLS_TV_MIN=14, K_LLS_TV_MAX=97)

#### 6. 手計算の実例（950 rpm / 20 kg/h）

    [アンカー ML=30]  D₃₀ = 49.0 %

理論上は正しい。`C = (90°−PM)·(π/180)/(Td·Ki)`、PM = 50° で C = 0.2257。

**実マップで解くと悪化する。** 低 `ML` 行が `kf_rf_soll` の下限 0.05 と `K_LLS_TV_MIN` = 14 %

**VE オートチューンを回すたびに位相余裕が動く。** 実装上の扱いは §9.11。

### 9.10 バルブ領域とスロットル領域は排他である（code + computed）

`egas_compute_throttle_target` @ `f:master:0270b0`（逐語）：

```c
if (ML_SOLL < ML_SOLL_MAX_LLS) { ML_SOLL_LLS = ML_SOLL;         ML_SOLL_WDK = 0; }
else                           { ML_SOLL_LLS = ML_SOLL_MAX_LLS; ML_SOLL_WDK = ML_SOLL - ML_SOLL_MAX_LLS; }
```

**上側では `ML_SOLL_LLS` が定数（`ML_SOLL_MAX_LLS`）に張り付く。**
`KF_LLS_TV` の入力が動かない ＝ **その傾きが一巡ゲインに一切寄与しない。**

| 領域 | 一巡ゲインを作るマップ |
|---|---|
| `ML_SOLL` **<** `ML_SOLL_MAX_LLS` | **`KF_LLS_TV`** × `KL_AQ_ABS_LLS` × `kf_rf_soll` |
| `ML_SOLL` **>** `ML_SOLL_MAX_LLS` | **`KF_EGAS_WDK`** × `KL_AQ_ABS_WDK` × `kf_rf_soll` |

**アクチュエータ側は完全に排他。`kf_rf_soll` だけが両方に効く。**

#### よくある誤読：「スロットルが吸収している」

直進では余ったバルブ開度をスロットルが閉じることで吸収し、旋回ではそれができない、
という読み方は**誤り**。**スロットルは両方とも 0.0 % のまま**（実測 362/362 行）で、
**床に張り付いていて動けない。**

吸収しているのは **`FR_REGLER`（積分器）**で、**時間さえあれば完全に吸収する**（積分器は定常偏差をゼロにする）。
旋回で崩れるのは吸収先が無いからではなく、**外乱が 0.3 Hz と速いから**である。
その周波数では位相余裕が 27–43° しかなく、**吸収どころか Q = 1.2–1.9 倍に増幅する。**

§9.3a がそれを直接示している：**強い区間と静かな区間で動作点は同じ**
（平均 duty 44.6 対 43.5、rpm 1132 対 1190）。プラントは変わらず、加振だけが変わった。

### 9.11 実装方針 — **別モード**（初稿の判断を撤回）

> **初稿は「この計算は固有の走行手順を持たないからモードではない」と書いた。誤り。**
> 手順はある — **微開で転がす走行**である。Session 954 がまさにそれで、86 秒、8–11 km/h、
> スロットル 0.0–0.1 %。**通常の VE 走行では、この領域に居続けない。**
> §9.10 の排他性が分かった時点で、初稿の前提は崩れていた。

#### 二つのモード

| | VE モード（既存） | **微開モード（新規）** |
|---|---|---|
| **走り方** | 普通に走る | **微開で転がす**（8–11 km/h、足を乗せるだけ） |
| **測るもの** | STFT / ラムダ | **`Td`（`duty`×`rpm` 相互相関）・動作帯・位相余裕** |
| **埋まる領域** | `aq_rel_rf` ≳ 1.2 %（スロットル領域） | **≲ 1.2 %（バルブ領域、下 9 行）** |
| **成果物** | `kf_rf_soll`（全域） | **`KF_LLS_TV`** |

走り方が違い、チャンネルが違い、領域が違い、成果物が違う。
**IDLE / INERTIA と同じ形**であり、`tsunagi-m-ux` §16 の「持続するモード」ではなく
**固有の手順を持つ作業単位**として既存 3 つと並ぶ。

#### ただし完全な分離ではない — 依存は一方通行

`kf_rf_soll` の**下 9 行は両モードが関わる**：

    VE モード    →  kf_rf_soll 全域を書く（下 9 行を含む）
    微開モード   →  kf_rf_soll の下 9 行を読んで KF_LLS_TV を逆引きする

- **微開モードは `kf_rf_soll` を書かない。読むだけ。**
- **VE を回すと微開モードの成果物が古くなる。**

#### 差の表示は、この 1 箇所のためだけに要る

`tsunagi-m-ux` §1「存在ではなく比較から導く」。ワークスペースは既に答えを持っている：

    ringMargin = PM( kf_rf_soll の下 9 行, KF_LLS_TV, KL_AQ_ABS_LLS,
                     kl_aq_rel_rf_fakt, KL_FR_INEG, Td, 動作帯 )
    ringDrift  = ringMargin < 閾値

**差が在る間だけ提示し、閉じれば自分で消える。** モードが 2 つに分かれたので、
これは「VE の成果物が微開モードの成果物より新しい」という**系譜の問題**として
一箇所で言える（§4「セッションと系譜」）。

#### 置き場所

| 何を | どこに |
|---|---|
| 純関数（マップ → マップ、サンプル不要） | `src/lib/lls/ringGain.ts` |
| `Td` と動作帯の抽出（ログ → 定数） | `src/lib/lls/fromLog.ts` |
| モードの面 | `src/components/LlsPanel.tsx` |
| 差の表示 | ハブに一行（VE を書いた直後に立つ） |
| `Td` の出所 | `measured` / `inferred` を明示（§15） |

`KF_LLS_TV` の書き手は **微開モード 1 つ**に保つ。
現在 `src/lib/idle/tuner.ts` が書いているので、**そちらからは外す**（§11「一つの仕事に一つの入口」）。

#### 手順

   §9.8 の表、§9.9-8 の位相余裕（39° → 47°）を再現できるか確かめる

## 10. 確定できなかったこと

- **`cfg_m.egas` の番地。** 0x8012 は XDF の定義であってコードから追った番地ではない。
  同じブロック（0x8006–0x8012）の他のバイトが軒並み妥当な値なので確度は高いが、
  **§5 の `LLS_TV` 実測で潰すこと。**
- **`fr_calc` のタスク周期。** 10 ms と仮定した（`K_FR_DI_ENTDR` の単位が %/10ms であることから）。
  セグメント同期なら §2 の「1 秒で振り切る」は回転数依存になる。
- **`ML_SOLL` の絶対スケール。** kg/h × 40 は `ramMap.ts` でも推定として扱われている。
  §5 で `ML_SOLL` と `ML_SOLL_MAX_LLS` を**同じ電文で**読めば、比較自体はスケールに依らず成立する。
- **ぐわんぐわんの実周波数。** `ramMap.ts` の注記は 1〜3 s の hunt を挙げている。
  実測できれば §2 と §4 のどちらの時定数に合うかで決着がつく。
- **`KL_LLS_UB_KORR` が全点ゼロ。** 電磁弁のデューティに電圧補正が無い。
  電圧が動く状況（PAS ポンプ負荷＝舵を切ったとき）で実開度が動く可能性があるが、
  `K_LLS_TV_DREHPUNKT` = 30.08 % 未満では補正分岐に入らないので、
  現状のデューティ域では**どちらにせよ無効**。
